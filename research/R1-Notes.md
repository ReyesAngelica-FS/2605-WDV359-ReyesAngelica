# Sub-Topic 1 - Feature Branch Workflow

Feature branch workflow is a development strategy where individual tasks, features, or fixes are completed within separate branches before being merged into the primary development branch. This process helps keep projects organized while allowing developers to safely test and manage updates without affecting stable code.

### Key Findings:

- Each feature or task should be developed in its own branch.
- Workflow structure follows:
  - feature branch → dev → staging → main
- Pull Requests help track development progress and document code changes.
- Feature branches improve organization and reduce the risk of breaking the main project environment.

---

# Sub-Topic 2 - Agile Workflow & Milestone Planning

Agile workflow focuses on iterative development, organization, and continuous progress throughout a project lifecycle. GitHub Issues, Milestones, and Project Boards are commonly used to manage tasks and monitor development progress.

### Key Findings:

- Milestones help organize work into manageable development periods.
- GitHub Issues can track development tasks, research, documentation, and feedback.
- Project Boards help visualize workflow progress using columns such as:
  - To Do
  - In Progress
  - Done
- Smaller task-focused issues improve productivity and project management.

---

# Sub-Topic 3 - Pull Requests & Collaborative Development

Pull Requests (PRs) are an essential part of collaborative development because they provide visibility into code changes before updates are merged into another branch.

### Key Findings:

- Pull Requests document development progress and provide a history of changes.
- PRs can be linked to Issues and Milestones for better project tracking.
- Merge conflicts can occur when multiple branches modify the same code.
- Reviewing changes through PRs helps maintain cleaner and more stable development practices.
